# 物体・車種・外観を追加する手順

## 責務

| ファイル | 管理する内容 |
|---|---|
| `src/catalog.ts` | 物体名・アイコン・部品・質量・形状・摩擦・反発・車軸位置・外観ID |
| `src/appearance.ts` | 外観IDとSVGの対応・描画サイズ・ローカル原点・描画順序 |
| `src/assets/*.svg` | 車体、タイヤ、木目、ボールの柄、背景 |
| `src/rendering.ts` | 定義を読み、部品の位置と角度に合わせて描く共通処理 |
| `src/physics.ts` | 共通の生成・回転接続・保持・脱落・配置・復元 |

追加ボタンとKind型はカタログのキーから生成するため、HTMLや入力処理に車種ごとの分岐は不要。
画像URLの読み込みは描画側に限定する。物理テストはブラウザや画像ファイルに依存しない。

## 新しい車種（パトカー・救急車など）

1. 車体SVGを用意し、車軸中心が合うようにローカル原点とm換算を決める。
2. `appearance.ts`にURLを`?url&no-inline`で登録する。`size`はm、`origin`は画像内の0〜1座標。タイヤには既存の`car-wheel`を再利用できる。
3. `catalog.ts`に新しいキーを追加し、`vehicleDefinition`へ以下の情報を渡す。
   - `version`・`label`・`icon`
   - `chassis`：形状、質量、摩擦、反発、外観ID
   - `wheel`：共通タイヤの形状、質量、摩擦、反発、外観ID
   - `axles`：車体のローカル座標で表した車軸位置の配列
4. 外観だけが違う車種は同じ形状・質量を再利用できる。救急車のように車体の大きさが変わる場合は、外観サイズ・物理形状・車軸位置を一緒に調整する。
5. 起動して追加・停止中の移動と回転・保持・走行・脱落・やりなおすを検証する。接続位置が違う車種では共通テスト合格だけで完成と判断しない。

車輪の数は`axles`の数で決まる。ユーザー向け接着や新しい接続方式を追加する必要はない。
車体の役割は`chassis`、車輪は`wheel`を維持することで既存の保持保護・脱落判定を使える。
パトカー・救急車・消防車を追加済み。点滅灯・サイレン・エンジンは未実装。車体の大きさと質量・車軸位置は車種ごとに定義する。

## ボール・単体物体

サッカーボールと野球ボールは`ballDefinition`を共用し、外観IDだけが違う。
現在の半径0.38m・質量1kg・摩擦・反発は両方同じ。実物の規格寸法や材質を再現したモードではない。
サイズを物理形状から自動算出する外観では、回転の中心と当たり判定が一致する。

## 三角・長方形の積み木

三角は凸多角形の`polygon.vertices`で定義し、頂点は部品のローカル座標（m）。今回の三角は重心が原点になるよう配置した。
Planckの凸多角形は最大8頂点。凸で、隣接頂点が重ならず、面積が正になる形を用意する。凹形状は分割の設計が必要。
衝突形状、密度算出、配置の重なり判定、壁境界、選択、保持アンカー、描画の輪郭は同じ頂点を使う。
SVGの余白を含めた範囲と物理形状を一致させれば、描画サイズと原点は形状の境界から自動算出する。
長方形は`box`の幅・高さを変え、木目外観を共用する。

## 描画と復元の注意

- 部品はIDごとに描画し、外れたタイヤも同じ画像で追従する。消去された部品の画像は破棄する。
- IDが再利用される場合も外観IDを確認してテクスチャを更新する。
- スナップショットは物体定義のキーとバージョンを保存する。互換性が変わる形状や接続の変更は定義バージョンを上げる。
- 描画専用の影・屋根・アーチは物理形状を自動生成しない。空洞や屋根まで厳密に当てたい場合は物理形状の追加設計が必要。
- 背景は`workshop.svg`の1600×900が16×9mに対応し、床の上端はy=860（8.6m）。背景の窓や壁模様には当たり判定がない。
- 固定坂道は板の形状だけを描く。支えを描く場合は、その部分の衝突仕様も先に決める。
- 新しい動作が必要な場合のみ共通処理の拡張を検討し、描画側から物理位置を書き換えない。
